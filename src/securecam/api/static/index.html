Video goes straight from the camera to this browser over WebRTC. The Raspberry Pi does not re-encode anything, so watching live costs it almost nothing.

Set up notifications

Notifications are sent by the Raspberry Pi itself, so they keep working while nobody has the web UI open. Everything below is edited on the Pi over SSH; there is no settings screen for it on purpose, because a stolen browser session must never be able to redirect your alarms.

1. Pick a provider

ntfy is free and needs no account: install the ntfy app, subscribe to a topic name that nobody else can guess, and you are done. Pushover costs a one-off fee but its emergency priority repeats the alert until you acknowledge it.

2. Edit the configuration

sudo nano /etc/securecam/config.yaml

For ntfy, the topic goes in recipients[].target, not in the ntfy block:

notifications:
  enabled: true
  provider: ntfy
  alarm: true
  include_snapshot: true
  # Only alert when the AI saw a person. Needs ai.enabled.
  only_if_person: false
  cooldown_seconds: 0
  ntfy:
    server: https://ntfy.sh
    priority: 5
  recipients:
    - id: phone
      enabled: true
      target: securecam-8f2b1c-choose-your-own

For Pushover, target is your user or group key instead:

notifications:
  enabled: true
  provider: pushover
  pushover:
    priority: 2
    retry_seconds: 30
    expire_seconds: 600
  recipients:
    - id: phone
      enabled: true
      target: uQiRzpo4DXghDmr9QzzfQu27cmVRsG

3. Add the secret

Tokens never live in config.yaml. They go in the environment file, which is only readable by root: 

sudo nano /etc/securecam/securecam.env
# ntfy only needs this for private servers or protected topics
SECURECAM_NTFY_TOKEN=tk_...
# Pushover always needs its application token
SECURECAM_PUSHOVER_TOKEN=azGDORePK8gMaC0QOYAMyEEuzJnyUi

4. Apply and test

sudo systemctl restart securecam
sudo securecam-admin test-notify

If nothing arrives, sudo securecam-admin diagnose prints which step failed and what to do about it. Failed notifications are retried automatically for 24 hours, so a short internet outage never loses an alert.

Connect it to an AI

The AI looks at a snapshot of each event and answers one question: was that a person? That answer is stored with the event and can be used to filter the event list and to hold back notifications for cats, branches and passing headlights.

1. Get an API key

The built-in provider is openai_vision, which works with the OpenAI API and with anything that speaks the same protocol. Create a key at your provider and keep it handy. Use generic_http instead if you run your own detection service.

2. Store the key

sudo nano /etc/securecam/securecam.env
SECURECAM_AI_API_KEY=sk-...
sudo chmod 600 /etc/securecam/securecam.env

3. Turn it on

sudo nano /etc/securecam/config.yaml
ai:
  enabled: true
  provider: openai_vision
  # More snapshots cost more. One is usually enough.
  snapshot_count: 1
  min_confidence: 0.6
  openai_vision:
    base_url: https://api.openai.com/v1
    model: gpt-4o-mini
    api_key_env: SECURECAM_AI_API_KEY
    detail: low
    max_tokens: 200

Point it at a different service by changing base_url and model.

4. Apply and test

sudo systemctl restart securecam
sudo securecam-admin test-ai

Keeping the bill small

  • detail: low and snapshot_count: 1 keep each call to a few tenths of a cent.
  • Disarming the camera stops recording and stops every AI call, so a disarmed camera costs nothing.
  • Recording never depends on the AI. If the key is wrong or the provider is down the clip is still saved, and the analysis is retried for 24 hours.
  • Set notifications.only_if_person: true once you trust the results, to cut down on false alarms rather than on cost.
